# cowork-lite

Claude Code를 안전하게, 설치 한 번으로 쓰게 해 주는 도구입니다. 내 파일을 AI가 마음대로 지우거나 덮어쓰지 못하게 지켜 주고, 업무 파일은 **작업 폴더** 한 곳(설치할 때 이름을 정합니다. 기본은 `cowork-space`)에 모읍니다. 업무는 폴더 하나씩으로 나눠 시작하고 완료하며, 하루 기록은 업무일지에 남습니다. 원하면 내 GitHub 비공개 저장소로 두 대의 컴퓨터가 같은 파일을 이어서 쓸 수 있습니다.

> **Mac**과 **Windows 11**에서 확인했습니다. Windows 10에서도 설치를 막지는 않지만 확인한 환경이 아니라서 일부 단계가 안 될 수 있습니다(설치 처음에 안내가 나옵니다). 아래에서 쓰는 컴퓨터에 맞는 쪽을 따라 하세요.

📖 **그림과 사용 예시가 있는 사용 가이드:** https://brief.wontae.click/ai/lite-guide

## 무엇을 해 주나요

| 기능 | 내용 |
|---|---|
| **안전장치(Guard)** | `받은자료`는 AI가 고치거나 지우지 못하고, `작업중`을 고치기 전에는 자동으로 사본을 남깁니다. 삭제는 확인을 거쳐 휴지통으로 옮깁니다 |
| **업무 폴더** | "업무 시작"·"업무 완료"·"완료한 업무 다시 하자"로 업무를 폴더 단위로 관리합니다 |
| **업무일지** | "세션 정리해"를 하면 오늘 한 일이 `업무일지/년-월/날짜.md`에 쌓이고, 동기화를 켰다면 바로 동기화됩니다 |
| **이어하기** | Claude Code를 시작할 때 진행 중인 업무와 가장 최근 세션 정리를 알려 줍니다 |
| **온보딩** | "온보딩"이라고 보내면 질문으로 내 업무에 맞게 설정합니다(양식·규칙·기준 데이터) |
| **전기 공무 스킬** | KEC 검토, 표준품셈·적산 보조, 공무 서류 작성(착공계·자재승인원·공정회의록 등) |
| **기본 스킬** | 기억(ai-memory), 웹 자동화(agent-browser), 스킬 찾기·만들기, MS 문서(xlsx·docx·pptx·pdf, MarkItDown), 한글 문서(HWP·HWPX) |
| **GitHub 동기화(선택)** | 두 대의 컴퓨터가 내 비공개 저장소로 같은 작업 폴더를 씁니다 |
| **점검(doctor)** | 설치와 설정이 제대로 되어 있는지 한 번에 확인합니다 |

## Claude Code에게 안내받으며 설치하기

Claude Code가 이미 있다면, 이 가이드 주소만 알려 주고 설치 안내와 설치 후 점검을 받을 수 있습니다.

1. Claude Code를 엽니다.
2. 아래 문장을 그대로 붙여넣습니다. (주소가 함께 들어 있어야 합니다)

   ```
   https://brief.wontae.click/ai/lite-guide 이 페이지를 읽고 cowork-lite 설치를 안내해 줘.
   ```

3. Claude가 컴퓨터 종류(Mac / Windows)를 확인하고, 설치로 바뀌는 내용을 설명한 뒤, 붙여넣을 **한 줄 명령**을 알려 줍니다. 그 명령은 **본인이 직접** PowerShell(Windows) 또는 터미널(Mac)에 붙여넣어 실행하세요. Windows는 Git이 없으면 설치기가 먼저 Git을 설치합니다(권한 확인 창이 뜨면 `예`). 그다음 설치기가 바뀌는 내용을 화면에 보여 주면 확인하고 `예`를 입력합니다.
4. 설치가 끝나면 새 창을 열고 Claude Code에 "설치 끝났어, 점검해 줘"라고 말합니다. Claude가 `cowork-lite doctor`를 실행해 결과를 알려 줍니다. 모두 ✔이면 끝입니다.

> 설치는 Claude 설정과 터미널 설정을 바꾸고 외부 프로그램을 내려받습니다. 그래서 가이드에는 Claude가 설치 명령을 대신 실행하거나 확인 질문을 건너뛰지 말고 사용자에게 안내만 하라고 적어 두었습니다. 이는 Claude에게 주는 지시일 뿐 기술적으로 막는 장치는 아닙니다. 설치 명령은 직접 실행하고, 설치기가 보여 주는 내용을 읽고 `예`를 입력하세요. Windows의 권한 확인 창과 Mac의 암호 입력도 본인이 처리합니다.

Claude Code 없이 직접 설치하려면 아래 설명을 따르세요.

## 설치하기 (Windows)

### 1단계. PowerShell 열기

1. 키보드의 `Windows` 키를 누릅니다.
2. **PowerShell**이라고 입력하고 엔터를 누릅니다. (관리자 권한으로 열 필요는 없습니다)

### 2단계. 설치 명령 붙여넣기

아래 한 줄을 복사해서 PowerShell 창에 붙여넣고(마우스 오른쪽 클릭) 엔터를 누릅니다.

```
irm https://raw.githubusercontent.com/WithWontae/cowork-lite/main/install.ps1 | iex
```

### 3단계. 화면의 안내 따라가기

- Git이 없으면 먼저 설치합니다. **권한 확인 창**이 나오면 `예`를 누르세요. 몇 분 걸릴 수 있습니다.
- 필요한 프로그램(Claude Code, Node.js)이 없으면 자동으로 설치합니다.
- 중간에 질문이 나옵니다. 아래 "설치 중 나오는 질문"을 보세요.
- 바뀌는 내용을 먼저 보여 드립니다. 확인하고 `예`를 입력하면 설치가 진행됩니다.
- 마지막에 **모두 초록불 ✔** 이 나오면 끝입니다. 이어서 안내되는 대로 Claude Code를 완전히 종료했다가 다시 열고 `온보딩`이라고 보내 보세요.
- `cowork-lite` 명령은 **새로 연 PowerShell·명령 프롬프트·Git Bash 창**부터 쓸 수 있습니다.

### 안 될 때 (Windows)

- "다시 실행해 주세요"라고 나오면 같은 명령을 한 번 더 붙여넣으세요. 끝낸 단계는 건너뛰고 이어서 진행합니다.
- 설치가 어디선가 실패하면 화면에 **종료 코드와 오류 문구**가 나오고, 같은 내용이 `%USERPROFILE%\.cowork-lite\install.log`에 남습니다. 도움을 요청할 때 이 파일을 함께 보여 주세요.
- 내려받는 단계는 시간 제한(최대 3분)이 있어서, 멈춘 것처럼 보이지 않고 인터넷·보안 프로그램 때문이면 이유를 보여 줍니다.
- 회사 PC에서 설치가 막히면 화면에 나온 "IT 담당자에게 요청할 내용"을 그대로 전달해 주세요. 개인 PC에서는 보통 관리자 권한이 필요 없습니다.
- 그래도 안 되면 새 창에서 `cowork-lite doctor`를 실행한 화면을 캡처해서 알려 주세요.

## 설치하기 (Mac)

### 1단계. 터미널 열기

1. 키보드에서 `⌘`(command)와 스페이스바를 함께 누릅니다.
2. 검색창에 **터미널**이라고 입력하고 엔터를 누릅니다.
3. 검은색(또는 흰색) 창이 열리면 준비가 끝났습니다.

### 2단계. 설치 명령 붙여넣기

아래 한 줄을 복사해서 터미널 창에 붙여넣고(`⌘`+`V`) 엔터를 누릅니다.

```
curl -fsSL https://raw.githubusercontent.com/WithWontae/cowork-lite/main/install.sh | bash
```

### 3단계. 화면의 안내 따라가기

- 필요한 프로그램(Claude Code, Node.js)이 없으면 자동으로 설치합니다. 몇 분 걸릴 수 있습니다.
- **암호 입력 창**이 나오면 Mac에 로그인할 때 쓰는 암호를 입력하세요. 입력해도 글자가 보이지 않는 것이 정상입니다.
- 중간에 질문이 나옵니다. 아래 "설치 중 나오는 질문"을 보세요.
- 바뀌는 내용을 먼저 보여 드립니다. 확인하고 `예`를 입력하면 설치가 진행됩니다.
- 마지막에 **모두 초록불 ✔** 이 나오면 끝입니다. 이어서 안내되는 대로 Claude Code를 완전히 종료했다가 다시 열고 `온보딩`이라고 보내 보세요.
- Mac은 MarkItDown용 Python을 자동으로 설치하지 않습니다. 필요하면 안내되는 주소(python.org)에서 3.10 이상을 설치한 뒤 `cowork-lite setup`을 다시 실행하세요.

### 안 될 때 (Mac)

- "터미널을 닫고 다시 열어 같은 명령을 한 번 더 붙여넣어 주세요"라고 나오면 그대로 하세요. 끝낸 단계는 건너뛰고 이어서 진행합니다.
- 설치가 실패하면 화면의 종료 코드와 오류 문구, `~/.cowork-lite/install.log`를 확인하세요.
- 회사 PC에서 설치가 막히면 화면에 나온 "IT 담당자에게 요청할 내용"을 그대로 전달해 주세요.
- 그래도 안 되면 `cowork-lite doctor`를 실행한 화면을 캡처해서 알려 주세요.

## 설치 중 나오는 질문

| 질문 | 답하는 방법 |
|---|---|
| **작업 폴더 이름** | 엔터를 치면 `cowork-space`. 내 홈 폴더 아래에 만들어집니다. 폴더에 쓸 수 없는 글자(`/ \ : * ? " < > |`)는 안 됩니다 |
| **GitHub에 동기화할까요?** | 두 대의 컴퓨터로 쓰거나 백업하려면 `예`, 이 컴퓨터에서만 쓰려면 엔터(건너뛰기). 나중에 `cowork-lite sync setup`으로 켤 수 있습니다 |
| **저장소 이름** (동기화를 `예`로 했을 때) | 엔터를 치면 `cowork-workspace`. 같은 이름의 내 비공개 저장소가 이미 있으면 그곳에 연결합니다 |
| **표시 이름** | 내 이름이나 별명입니다(설정에 저장됩니다). 엔터를 치면 기본값을 씁니다 |
| **이대로 설치할까요?** | 바뀌는 내용을 읽고 `예` |

설치되는 것: Claude Code, Node.js, 기본 스킬 5종, 직접 만든 스킬 4종(온보딩, 전기 공무 3종), 안전장치(hook) 2개, 그리고 동기화를 `예`로 했다면 Git과 GitHub CLI(`gh`)입니다. MS 문서 변환 도구(MarkItDown)를 위해 **Python**을 설치합니다. Windows는 winget이 없거나 실패하면 python.org의 공식 설치 파일(서명을 확인한 파일만 실행)로 설치하고, MarkItDown이 쓰는 **Microsoft Visual C++ 런타임**이 없으면 함께 설치합니다(권한 확인 창이 한 번 뜰 수 있습니다). Python이 없어도 문서 스킬 자체는 정상이고 MarkItDown만 빠지며, 이때 doctor가 ⚠ 경고로 알려 줍니다.

## 설치 뒤 처음 할 일: 온보딩

설치가 끝나면 Claude Code를 열고 **`온보딩`** 이라고 보내 보세요. 몇 가지 질문으로 내 업무에 맞게 설정해 줍니다. 모르는 질문은 "나중에"라고 해도 됩니다.

- **전기 공무**: 자주 쓰는 서류의 회사 양식과 작성 규칙을 정하고, KEC·품셈 같은 기준 데이터는 **내가 가진 공식 자료**를 받아 표로 확인한 뒤 저장합니다. AI가 아는 값으로 임의로 채우지 않습니다.
- **그 밖의 업무**: 주요 업무와 반복해서 만드는 서류, 지켜야 할 규칙을 물어 정리해 둡니다.
- 입력한 내용은 이 컴퓨터의 작업 폴더(`.cowork/`)에만 저장되고, 동기화를 켰다면 내 비공개 저장소로 두 대의 컴퓨터가 함께 씁니다.
- 처음 Claude Code를 열 때 Claude가 한 번 안내합니다. 나중에 한 부분만 다시 하려면 "온보딩 수정"이라고 하세요.

## 사용하기

평소에는 Claude Code에게 말로 시키면 됩니다. 예를 들면 이렇게 말하세요.

> 받은자료에 있는 견적서 3개를 엑셀 비교표로 만들어 줘

파일은 작업 폴더에 모입니다.

| 폴더 | 용도 |
|---|---|
| `받은자료` | 받은 원본. AI가 고치거나 지우지 못합니다 |
| `작업중` | 진행 중인 업무 폴더(`001_견적서 비교` 같은 `번호_이름`)가 있는 곳. 고치기 전에 자동으로 사본을 남깁니다 |
| `결과물` | 완료한 업무 폴더가 통째로 옮겨지는 곳 |
| `업무일지` | 세션 정리가 쌓이는 곳(`2026-11/2026-11-20.md`처럼 월 폴더 아래 날짜 파일) |

파일을 지울 때는 바로 지워지지 않고 확인을 거쳐 휴지통 폴더로 옮겨집니다. 되돌릴 수도 있습니다.

### 업무 시작·완료

업무 하나는 폴더 하나입니다(`작업중/001_견적서 비교/`처럼 `번호_이름`). Claude Code에게 이렇게 말하세요.

| 말 | 하는 일 |
|---|---|
| **업무 시작** | 진행 중인 업무 목록이 나오고, 맨 아래에 "새로운 업무 시작"이 있습니다. 새 업무면 이름을 정해 폴더를 만들고, 기존 업무를 고르면 3줄 요약을 보여 준 뒤 그 폴더에서 이어서 일합니다 |
| **업무 완료** | 그 업무 폴더를 통째로 `결과물` 폴더로 옮깁니다. 같은 이름이 이미 있으면 덮어쓰지 않습니다 |
| **완료한 업무 다시 하자** | 완료한 업무 중에서 골라 `작업중`으로 다시 가져옵니다 |
| **세션 정리해** | 오늘 한 일·결정·남은 일을 업무일지에 덧붙이고, 동기화를 켰다면 바로 동기화까지 합니다 |

- 업무 번호는 작업중과 결과물 전체에서 가장 큰 번호에 1을 더해 매겨서, 완료했다가 다시 가져와도 이름이 같고 번호가 겹치지 않습니다. 업무를 가리킬 때는 번호(`3`, `003`)나 이름 일부 어느 것이든 됩니다.
- 업무 안의 파일은 그 업무 폴더 안에서 만들고 고치고 지웁니다. 지울 때는 평소처럼 확인을 거쳐 휴지통으로 갑니다.
- `001_`처럼 숫자와 `_`로 시작하지 않는 폴더·파일은 업무로 보지 않고 건드리지 않습니다. 예전에 만든 파일은 그대로 남습니다.

### 업무일지와 이어하기

- **"세션 정리해"**를 하면 `업무일지/2026-11/2026-11-20.md`처럼 월 폴더 아래 날짜 파일에 `## 세션 정리 14:05` 구역과 진행 중 업무 목록이 **덧붙여집니다**(먼저 쓴 내용은 지우지 않습니다). 동기화를 켰다면 이어서 바로 동기화하고, 실패해도 업무일지는 이 컴퓨터에 저장되어 있으며 이유를 알려 줍니다.
- **이어하기:** Claude Code를 시작할 때(다른 컴퓨터의 변경을 받은 뒤) 진행 중인 업무 최대 3건과 가장 최근 세션 정리 3줄이 안내됩니다. 그대로 "이어서"라고 하면 됩니다.
- **기록 점검:** 업무일지는 GitHub 비공개 저장소로 올라갈 수 있어서, 쓰기 전에 본문을 점검합니다. 비밀번호·토큰처럼 보이는 줄은 **쓰지 않고**, 휴대전화·전화번호·이메일·주민등록번호·카드번호처럼 보이는 줄은 쓰되 "거래처 1곳처럼 일반화하세요"라고 경고합니다. 경고에는 값이 아니라 종류와 줄 번호만 나옵니다. 모양만 보는 점검이라 놓치거나 잘못 잡을 수 있으니, 민감정보는 처음부터 적지 마세요.

### 전기 공무 스킬

설치되는 직접 만든 스킬 3종입니다. 해당 요청을 하면 Claude가 알아서 씁니다.

| 스킬 | 이럴 때 | 하는 일 |
|---|---|---|
| **KEC 검토** | "전선 굵기 맞아?", "전압강하 계산해 줘" | 차단기 용량·전선 굵기, 접지·이격거리, 전압강하를 KEC 기준으로 점검합니다 |
| **표준품셈·적산 보조** | "일위대가 검증해 줘", "설계변경 단가 근거" | 공종별 품셈·노임·할증으로 일위대가를 계산하고 근거표를 만듭니다 |
| **공무 서류** | "자재승인원 초안", "착공계", "공정회의록" | 회사 양식의 빈칸을 채워 서류 초안을 만듭니다 |

- **기준 데이터(KEC 조항, 허용전류, 품셈, 노임, 할증)는 제가 만들어 넣지 않습니다.** 내가 가진 공식 자료를 `온보딩`으로 넣어야 하고, 비어 있으면 스킬이 멈추고 "온보딩을 먼저 해 주세요"라고 안내합니다.
- 모든 결과에는 "참고용 초안입니다. 담당자가 확인하세요"가 붙습니다. 최종 판단은 사람이 합니다.
- 회사 양식은 작업 폴더의 `양식/` 폴더에 넣어 두면 됩니다.

## 두 대의 컴퓨터에서 같이 쓰기 (GitHub 동기화)

동기화는 **선택**입니다. 켜면 작업 폴더가 **내 GitHub 계정의 비공개 저장소**에 저장되어, 노트북 두 대에서 같은 파일을 이어서 쓸 수 있습니다. 끄면 이 컴퓨터에서만 씁니다. 공개 저장소로는 절대 올리지 않습니다(공개 저장소를 만나면 연결을 거절합니다).

**언제 맞춰지나요?**

- Claude Code를 **시작할 때** 다른 컴퓨터가 올린 변경을 받고, 못 올린 변경을 올립니다.
- Claude Code를 **끝낼 때** 바뀐 파일을 자동으로 올립니다. 창을 강제로 닫지 말고 `/exit` 으로 정상 종료하세요.
- **"세션 정리해"**를 하면 업무일지를 쓴 뒤 바로 동기화합니다.
- 바로 맞추고 싶으면 `cowork-lite sync` 를 실행합니다.

**처음 켜기 (첫 번째 컴퓨터)**

1. 설치할 때 "GitHub에 동기화할까요?"에서 `예`를 고릅니다. (나중에 켜려면 `cowork-lite sync setup`)
2. GitHub에 로그인합니다. (GitHub 계정이 필요합니다)
3. 저장소 이름을 묻습니다. 엔터를 치면 기본 이름(`cowork-workspace`)을 씁니다. 같은 이름의 **내 비공개 저장소가 이미 있으면 그것에 연결**하고, 없으면 만들어도 되는지 확인한 뒤 만듭니다.

**두 번째 컴퓨터 연결하기**

1. 두 번째 컴퓨터에도 같은 방법으로 설치합니다.
2. "GitHub에 동기화할까요?"에서 `예`, **같은 GitHub 계정**으로 로그인합니다.
3. 저장소 이름에 **첫 번째 컴퓨터에서 쓴 이름을 그대로** 입력합니다. "이미 있어서 연결합니다"라고 나오면 성공입니다.
4. 작업 폴더 이름은 컴퓨터마다 달라도 됩니다.

**같은 파일을 양쪽에서 고쳤다면**

어느 쪽 내용도 지우지 않습니다. 이 컴퓨터의 파일은 그대로 두고, 다른 컴퓨터의 내용은 `파일이름.충돌-<컴퓨터이름>` 사본으로 남깁니다. `cowork-lite sync resolve` 를 실행하면 정리하는 방법을 알려 주고, Claude에게 "충돌 사본 정리해 줘"라고 해도 됩니다.

**알아 두세요**

- 크기 제한을 넘는 큰 파일과 비밀값으로 보이는 파일은 올리지 않고, 올리지 않았다고 알려 줍니다. 그 파일은 그 컴퓨터에만 있습니다.
- 두 컴퓨터에서 오프라인으로 같은 번호의 업무를 각각 만들면 폴더가 나란히 남고 번호만 겹칩니다. 번호 대신 전체 이름으로 가리키면 되고, `cowork-lite doctor`가 알려 줍니다.
- 업무 파일이 GitHub로 올라가므로, 회사 보안 규정이 허용하는지 먼저 확인하세요. 모르면 "건너뛰기"를 고르세요.
- GitHub 계정에는 **2단계 인증**을 켜 두세요.
- 상태는 `cowork-lite sync status`, 설치 상태는 `cowork-lite doctor` 의 "마지막 동기화" 줄로 볼 수 있습니다.

## 자주 쓰는 명령

평소에는 말로 시키면 Claude가 알아서 실행하므로, 직접 칠 일은 많지 않습니다.

| 명령 | 하는 일 |
|---|---|
| `cowork-lite doctor` | 설치와 설정, 업무 폴더 상태를 점검합니다 |
| `cowork-lite setup` | 설치를 이어서 진행하거나 다시 점검합니다(끝난 단계는 건너뜁니다) |
| `cowork-lite task list` | 진행 중인 업무를 봅니다(`--done`은 완료한 업무) |
| `cowork-lite task new "견적서 비교"` | 새 업무 폴더를 만듭니다 |
| `cowork-lite task show 3` | 진행 중인 업무를 3줄로 요약합니다 |
| `cowork-lite task done 3` | 업무 폴더를 통째로 결과물로 옮깁니다 |
| `cowork-lite task reopen 3` | 완료한 업무를 작업중으로 다시 가져옵니다 |
| `cowork-lite session save "오늘 한 일"` | 업무일지에 덧붙이고, 동기화를 켰다면 바로 동기화합니다 |
| `cowork-lite sync` | (동기화를 켠 경우) 다른 컴퓨터와 맞춥니다: 받기 → 올리기 |
| `cowork-lite sync status` | 연결 상태와 마지막 동기화를 봅니다 |
| `cowork-lite sync resolve` | 같은 파일을 양쪽에서 고쳤을 때 정리하는 방법을 알려 줍니다 |
| `cowork-lite space ls` | 작업 폴더 목록을 봅니다 |
| `cowork-lite space find 견적서` | 파일을 찾습니다 |
| `cowork-lite space rm 작업중/001_견적서 비교/파일.xlsx` | 확인 후 휴지통으로 옮깁니다 |
| `cowork-lite space restore 작업중/001_견적서 비교/파일.xlsx` | 휴지통에서 되돌립니다 |

## 제거하기

```
cowork-lite uninstall
```

작업 폴더의 파일은 지우지 않습니다. 직접 만든 스킬(온보딩, 전기 공무)도 함께 지우지만, 같은 이름으로 직접 만들어 둔 스킬은 건드리지 않습니다. Windows에서는 PowerShell 환경 변수(PATH)에 추가했던 항목도 되돌립니다.

## 알아 두세요

- Windows에서는 Claude Code가 안전장치를 실행할 때 **Git Bash**를 씁니다. 그래서 설치할 때 Git이 함께 설치됩니다.
- 이 도구의 안전장치는 **실수를 막아 주는 장치**입니다. 일부러 우회하려는 시도까지 막지는 못합니다.
- 비밀번호·인증서·주민번호·계좌 같은 민감정보는 AI에게 기억시키지 마세요. 업무일지의 기록 점검은 모양만 보는 안내라서 놓칠 수 있습니다.
- 전기 공무 스킬의 계산·검토 결과는 참고용 초안입니다. KEC·품셈 같은 기준은 내가 확인한 공식 원문이 기준입니다.
