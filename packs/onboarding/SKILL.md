# 온보딩 인터뷰

사용자의 업무에 맞게 설정을 채우는 대화다. **쉬운 말로, 한 번에 질문 1~2개만** 한다. 사용자는 개발자가 아니다.

## 0. 시작

1. 작업 폴더의 `.cowork/onboarding.json` 을 읽는다.
   - 없으면 새로 시작한다.
   - 있으면 완료한 단계를 보여 주고 "이어서 / 처음부터 / 한 부분만 수정" 중 고르게 한다.
2. 시작할 때 이렇게 알린다: "몇 가지 질문으로 업무에 맞게 설정해 드릴게요. 모르면 '나중에'라고 하셔도 됩니다. 입력하신 내용은 이 컴퓨터의 작업 폴더에만 저장됩니다."
3. 각 단계가 끝날 때마다 `onboarding.json` 에 단계·요약·날짜를 저장한다(중간에 멈춰도 이어갈 수 있게).

## 1. 업무 확인

"어떤 일을 하세요?" — 전기 공무 / 그 외(직접 말씀). 여러 개면 하나씩 차례로 한다.

## 2A. 전기 공무

### ① 양식과 작성 규칙
- 자주 만드는 서류를 묻는다(착공계, 자재승인원, 주간 공정보고서 등).
- 서류마다 회사 양식 파일을 `양식/` 폴더에 넣도록 안내한다.
- 서류마다 항목 순서, 꼭 들어가는 내용, 파일 이름 규칙을 묻고 요약해 `.cowork/rules/<서류이름>.md` 에 저장한다.

### ② 기준 데이터
항목마다 "이게 무엇이고 어디에 쓰이는지"를 한 줄로 설명한 뒤 자료를 받는다.

| 데이터 | 저장 파일(`.cowork/data/elec-works/`) | 받을 자료 |
|---|---|---|
| KEC 조항 | `kec-clauses.csv` (조항, 내용, 출처, 기준일) | KEC 원문에서 자주 쓰는 조항 |
| 허용전류 | `cable-ampacity.csv` | 전선 허용전류표 |
| 전압강하 계수 | `voltage-drop-formulas.json` | 사용하는 계산식과 계수 |
| 품셈 수량 | `labor-norms.csv` | 쓰는 공종의 품셈 |
| 노임 단가 | `unit-wages.csv` | 해당 연도 노임 |
| 할증 | `surcharge-rules.csv` | 적용하는 할증 조건 |

규칙:
- **사용자가 준 자료에서만 옮긴다.** PDF·엑셀은 `python -m markitdown <파일>`, 한글 파일은 `kordoc` 스킬로 읽는다.
- **내가 아는 값으로 채우지 않는다.** 자료가 없으면 비워 두고 "나중에"로 표시한다.
- 옮긴 내용을 **표로 보여 주고 "맞나요?"** 확인을 받은 뒤에만 저장한다. 틀린 행은 그 자리에서 고친다.
- 출처(문서 이름·조항·판)와 기준일(개정일·적용 연도)을 자료에서 읽거나 사용자에게 묻는다. 말로 불러 준 값은 출처를 `사용자 입력(미확인)` 으로 적는다.

### ③ 시험 실행
실제 서류 1건(또는 계산 1건)으로 해당 스킬을 돌려 결과를 같이 본다. 틀린 점은 규칙·데이터를 고친다.

## 2B. 그 외 업무

차례대로 묻는다: 주요 업무 3가지 → 반복해서 만드는 서류 → 서류마다 **받는 것·내는 것·지켜야 할 규칙** → 외부로 나가는 것(메일·제출)이 있는지 → 자주 하는 실수.

- 정리한 내용을 `.cowork/playbooks/<업무이름>.md` 에 저장한다(업무 절차와 양식 규칙).
- **서류 샘플 원본은 복사하지 않는다.** 양식 규칙만 남긴다. 개인정보·거래처 정보는 가려 달라고 안내한다.

## 3. 마무리

- 저장한 것, 비어 있는 것(나중에 채울 것)을 목록으로 보여 준다.
- 앞으로 쓸 수 있는 말을 예로 들어 준다(예: "이번 주 공정보고서 만들어 줘").
- 동기화가 켜져 있으면 "다른 노트북에서도 같은 설정이 쓰입니다"라고 알린다.
- "나중에 '온보딩 수정'이라고 하시면 한 부분만 다시 할 수 있어요"라고 알린다.

## 지킬 것

- 저장은 모두 **작업 폴더 안**에만 한다. `받은자료/` 는 수정하지 않는다.
- 비밀번호·주민등록번호·계좌 같은 민감정보는 받지 않는다. 입력하려 하면 멈추게 하고 안내한다.
- 외부로 보내거나 제출하는 일은 하지 않는다.
